# Static Client and Host operation contract

This installed plugin uses the public Connection RPC carrier. When connection and webServer are available, Host registers connection.rpc.handle('/agentdeck', handler) and accepts namespaced agentdeck.* methods. The native API Gateway owns the exclusive shared /api interceptor. On the pinned 0.2.2-rc.3 baseline, explicitly call the public HostConnectionService.prototype rpc getter with the consumer service proxy; ordinary getter access shadows the dependency context and makes native handle() unable to read webServer. Both dependencies must still be declared by the consumer. This binding changes no service state or native registration logic. The dedicated channel retains native Host/Origin and authentication checks. Its handler admits only owner peers, validates payloads, and calls the same operation functions used by agent tools. UI-only save/reset/import operations are not model authority grants and must never mutate native model authorization.

## Client integration

Author src/client/index.js as one self-contained window.__ModuleLoader__.load({id:'dsh-agentdeck',factory(require){...}}) factory. React=require('react'); return {inject:['slots','locale','connection'],apply(ctx){...}}. No React copy, external client package imports, CDN, raw API fetch, or alternate app root. Use ctx.get('connection').rpc.call('/agentdeck', endpoint, payload, signal), unwrap the returned result DIRECTLY ({ok:true,value}|{ok:false,error}); connection.rpc.call does not return an outer response.result wrapper. Register settings.section id='agentdeck', order=30, label localized via ctx.locale; settings.section.icon keyed 'agentdeck' optional. Exact slot has close owner prop plus standard usePanelInfo/useSessions hooks. Can run without active Session; an optional explicit session id selects Session-authorized metadata. Use native theme tokens only (bg-base/layer-1/layer-2, border-l1/l2, label-primary/secondary, brand-primary, state-error/success/warn/idle-primary). Route all visible copy through registered zh/en locale dictionary. Maintain abort-on-unmount. Catalogue/models/preview/runs/result reads have a 15000 ms Client deadline, abort their carrier on timeout, end the busy state even if a carrier does not settle, preserve drafts, and expose a localized retryable error. Superseded/unmounted reads remain silent. Save/reset have no automatic deadline or replay. Show a preview only when both role id and revision match the current definition. Runtime capability evidence is retained per role, revision and selected Session so switching roles does not make a previously verified list row contradict its detail. Starting a refresh cancels the preceding preview and clears all evidence before loading the catalog; starting any preview clears that role’s earlier evidence. Candidate detail facts require a matching candidate; list authorization still describes the saved default. Failed or timed-out previews leave list/detail readiness unverified until a current request succeeds; late responses cannot restore expired evidence.

## Operations and shapes

- agentdeck.catalog payload {sessionId?:string}: {agents: AgentView[], diagnostics: {id?,source?,message}[], overrides: {id,text,revision}[], runtime:{compatibilityVersion:string,nativeProvider:boolean,storage:boolean}, sessions:{id,title?,cwd?}[]}.
- AgentView is AgentDefinition (docs/core-contract.md) plus source?:string (external owning layer), revision:string, available:boolean, capabilitiesAvailable:boolean, authorization:{status:'unknown'|'authorized'|'denied',code?,policy?,route?,allowedModels?,message?}, configuredSelection?, missingCapabilities:string[], unverifiedCapabilities:string[], capabilityCheck:'static', builtin:boolean. `capabilitiesAvailable` records capability/enablement readiness; `available` additionally requires the saved default route to be authorized for the selected Session. No Session means unknown authorization and `available:false`. Catalog reads sample the Session policy once and do not discover model metadata. Matching live preview evidence can update list capability readiness, while a candidate preview must retain the saved default authorization in the list. Invalid candidate previews remain unavailable/unverified. Denial code `AGENTDECK_MODEL_NOT_AUTHORIZED` carries allowed explicit routes and owner recovery: change the saved role model or configure native model-selection settings and create a new Session; settings do not grant a restored Session new routes. AgentView also has browserSupport:{backend:'mcp'|'bsk'|'none',state:'ready'|'unverified'|'unsupported',reason:string,allowedNames:string[]}. Readiness means admitted tools, with live native connection checks still required. Static advisory reads must not initialize dynamic ToolSets or audit historical presets. Unknown dynamic capability is distinct from a proven missing prerequisite; actual child resolution/guards still apply. Model discovery is not authorization.
- agentdeck.models payload {sessionId?:string,provider?:string,model?:string,view?:'options'|'setup-options'}: {providers:{id,name}[],models:ModelView[],selection?:{provider,model,reasoningEffort?},policy:'session'|'parent-only'|'not-selected',explicitRoutes?:{provider,model}[],diagnostics:string[]}. Explicit unscoped tool queries retain full-directory metadata behavior. GUI options mode with no provider reads registered provider names and the Session's explicit route policy without model discovery. The provider filter lists only that provider without per-row metadata, and provider+model resolves only that route. The separate setup-options view lists globally configured providers and, with a provider filter, that provider's listed models. It ignores Session policy and performs no exact metadata lookup. The AI generator field also accepts a typed model ID. A provider list does not gate exact metadata. Candidate provider and model fields are native select controls backed by registered providers and that provider's configured model options. The Client scopes option membership, busy/error state, deadlines and retry identity by provider; exact metadata is scoped by provider/model. Lists load lazily on focus or route selection, share only within the same provider and never resolve every candidate's metadata. Missing saved values remain explicit unavailable/unchecked options rather than being silently rewritten. Changing a candidate route clears only that candidate's effort, retaining its output cap, the default candidate and other candidates. The Client stores option membership separately from exact metadata, replaces list membership on refresh and exposes list diagnostics with retry.
- ModelView: {provider,id,name,authorized:boolean|null,metadataResolved:boolean,contextWindow?:number,defaultMaxTokens?:number,efforts?:{id,name,description?}[],defaultEffort?:string,inputModalities?:string[],error?:string}. Unresolved options omit efforts rather than claiming an empty supported set. An exact request includes exact metadata even if the catalogue omitted it. A non-session view has authorized:null. Unknown values must remain unknown.
- agentdeck.preview payload {id:string,sessionId?:string,candidateId?:string,revision?:string}: {agent:AgentView,model?:ModelView,configuredSelection?,effectiveSelection?,sessionSelection?,authorization:{status:'unknown'|'authorized'|'denied',message?},output:{configuredMaxTokens?,effectiveMaxTokens?,source:'candidate'|'role'|'parent'|'native-default'|'unknown',validated:boolean},capacity:{kind:'configured'|'validated-parameters'|'unknown',assemblyChecked:false},budget:{known,targetTokens,elasticTokens,safeInputTokens?,headroomTokens,materialTokens?,diagnostics},diagnostics:string[]}. Fixed/auto metadata can resolve without a Session; authorization is unknown and the cap is configured only. A denied route retains declaration metadata. Unmeasured fixed prompt/tool cost means materialTokens is omitted; safeInputTokens is total-input capacity, not a free-material estimate. Actual execution still validates assembly.
- agentdeck.candidates payload {id:string,sessionId?:string}: {id,revision,mode,defaultCandidate?,candidates:{id,purpose,provider,model,reasoning,maxTokens,authorization:'unknown'|'authorized'|'denied'}[]}. Only this role's compact pool is returned, without instructions, other pools or model directory/metadata calls. Auto starts require this revision; candidateId and candidateReason are optional, the default is explicit, and invalid/unauthorized/stale choices never start another candidate.
- Owner-only `agentdeck.inspectDefinition` accepts `{text}` and returns `{id}` from bounded strict parsing. The Client binds this identity to the exact draft text before deciding whether to create or target an existing override.
- Owner-only `agentdeck.previewChange` accepts `{id,text?,actions?,reset?,expectedRevision?,sessionId?}`. Save preflight takes exactly one of YAML text and sparse form actions. Reset preflight takes `reset:true` and the current override revision. Actions are limited to editable schema fields and support set, delete-local and explicit output clear. The Host materializes them on the stored YAML document or on a minimal factory override. The result includes the exact final YAML or deletion intent, the existing override text and revision, direct before/after definitions, diagnostics, indirect impacts and `impactRevision`.
- Owner-only `agentdeck.save` accepts `{id,text,expectedRevision?,impactRevision?,acceptedIndirectRoles?,sessionId?}` and returns `{id,revision,text}`. Text is a schema v1/v2 YAML override. A new role uses `extends` or a complete definition. Replacing an override requires its current revision. Source-owned definitions are edited in their owning file or derived to a fresh ID. Factory definitions are immutable. The Client submits the exact previewed text. A lost or malformed response triggers readback against the same scope. An exact match is reported as observed and an inconclusive result preserves the draft.
- Owner-only `agentdeck.reset` accepts `{id,expectedRevision,impactRevision?,acceptedIndirectRoles?,sessionId?}` and returns `{id,reset:true}`. It deletes only the target override from the plugin store. All single writes recalculate preflight inside the serial CAS boundary and reject indirect role loss. Legacy model tools reject writes with `AGENTDECK_OWNER_CONFIGURATION_REQUIRED`.
- Owner-only agentdeck.recommend accepts one of three forms: the explicit strategy contract described below; the legacy payload {roleIds:string[],defaultRoute:{provider,model},imageRoute?:{provider,model},includeBrowser?:boolean,sessionId?:string}; or an AI proposal request {roleIds:string[],generatorRoute?:{provider,model},scopePolicy?:'fill-unconfigured'|'replace-selected',includeBrowser?:boolean,browserStrategy?:SetupStrategy,resourceMigration?:{[roleId]:Migration},sessionId?:string} with neither strategy nor legacy routes. Legacy calls retain fixed-model semantics; legacy route fields must not be mixed with strategy fields. When roles need generation, the host uses the owner-selected generatorRoute for one native llm.stream request. The generator can be chosen without a Session. For compatibility, callers that omit generatorRoute can use the selected Session's delegationSelection. The model receives role responsibilities, selected constraints and resolved candidate routes, and must return a strict JSON object with a `strategies` map containing one auto strategy per requested role included in generation. The host accepts a bare object or a single enclosing Markdown JSON fence, rejects a token-limit finish before decoding, and bounds the requested output by the generator model’s configured default when declared. Before streaming, the host rejects a generator that explicitly lacks text input and checks that the estimated input, requested output, and headroom fit the declared context window when available. Excluded browser roles, source-owned roles, and roles protected by the scope policy are preserved without a generated strategy. Browser roles with an explicit browser strategy skip generation and are identified as owner-selected; their routes must pass the same allowlist. No model request is made if no selected roles need generation. The prompt and accumulated response chunks each have a 256 KiB UTF-8 budget. The generator input omits routes that explicitly lack text input or whose metadata failed to resolve. Metadata failures are reported when a proposal can still be generated. The host rejects the proposal if a selected role revision changes between catalog reads. The host rejects malformed JSON, unselected role IDs, and unavailable or unauthorized generators. A missing or invalid generated strategy, including a candidate route that is unavailable, unauthorized, or explicitly lacks text input, blocks only its own row. Valid strategies still pass the local metadata, authorization, effort, capacity, scope and revision checks. Generation returns {rows,models,diagnostics,setupPolicy?,proposalSource?,proposalGenerator?}, never persists, and never lets model output bypass native delegation or preview/apply preflight.
- Owner-only agentdeck.previewSetup payload {rows:{id,text,roleRevision,expectedRevision?}[],setupPolicy?:{scopePolicy},sessionId?:string}: {resources:{[roleId]:{model,reasoning,output?,context}},impacts,impactRevision}. It reuses apply preflight and resolves every saved prefix without persistence or model calls. Each prefix must preserve all roles resolved in the selected Session and global catalogs, even if a later row would restore a role. The Client rechecks the exact clean checked subset, including after checkbox changes. Pending, failed or incomplete previews hide stale after-values and disable saving. Obsolete responses cannot replace a newer subset or restore old acceptance.
- Owner-only agentdeck.applySetup payload {rows:{id,text,roleRevision,expectedRevision?}[],setupPolicy?:{scopePolicy},impactRevision?:string,acceptedIndirectRoles?:string[],sessionId?:string}: {status:'completed'|'stopped',rows:{id,status:'applied'|'failed'|'uncertain'|'not-run',revision?,message?}[]}. Strategy calls include the preview policy and revision. Every call with indirect impacts must supply the exact preview revision and accept every affected role. Preflight recomputes them before writing. Base roles precede derived roles; each prefix rechecks catalog/source revisions within the serial store boundary. First failure stops later rows and retains confirmed writes. There is no cross-role atomicity, rollback, persistent journal or automatic resume/replay. Lost responses trigger catalog readback; exact matching text is observed, not attributed to that request. Canceled or superseded readback stays silent; actual readback failure reports unknown outcomes.
- `agentdeck.runs` accepts `{parentId?,sessionId?}` and returns `{runs:RunView[],parentIds:string[]}`. Owner requests may filter by recorded parent ID, including historical Sessions. Agent callers are confined to their exact parent Session. Results cover the latest 200 matching records. Normal rows use lightweight native residency state. Uncertain startup receipts retain separate native reconciliation.
- RunView: {id,roleId,revision,parentId,childId?,description,createdAt,phase:'starting'|'accepted'|'uncertain'|'failed',error?,model?:{provider,model,reasoningEffort?,maxTokens?},decision?:{candidateId,roleRevision,source:'default'|'recommended'|'legacy-route',reason?},nativeStatus?:string}. The Client augments a row with business status and verification time after reading current result detail. Refresh, a new detail check, or a stale paging revision invalidates old verified summaries.
- agentdeck.result payload {childId:string,sessionId?:string,offset?:number,limit?:number,resultRevision?:string}: {childId,status,summary,evidence?:unknown[],coverage?:unknown,artifacts?:unknown[],limitations?:unknown[],rawText:string,totalCharacters:number,nextOffset?:number,resultRevision?:string,usage?:unknown,nativeStop?:unknown}. For offset > 0 both the owner RPC and the model tool require the first page’s resultRevision. The RPC returns AGENTDECK_RESULT_CHANGED when the revision is missing or stale. The Client preserves loaded text, marks the outcome unverified and offers a first-page reload. Usage-only updates do not change the revision. Idle or absent residency alone provides no completion proof. The latest native turn and stop reason constrain completion claims. A single structured evidence/artifact/limitation value is normalized to an array rather than discarded. Native usage is reported only where available; absent counters remain null and a wholly unreported usage record is null. Runs queries reconcile uncertain receipts against native catalogue and exact parent/preset metadata without creating work.

## Progressive batch setup

The explicit-strategy owner-only recommend payload is {roleIds:string[],strategy:SetupStrategy,scopePolicy?:'fill-unconfigured'|'replace-selected',includeBrowser?:boolean,browserStrategy?:SetupStrategy,resourceMigration?:{[roleId]:Migration},sessionId?:string}. The AI form omits strategy and legacy route fields and may include generatorRoute:{provider,model}; the Client sends the same scope, browser and migration constraints and does not require a prebuilt candidate pool. Default scope policy is fill-unconfigured; it preserves existing overrides and disabled roles. Source-owned roles are never writable here. The Client also excludes dirty drafts; unlocking replacement only enables manual selection and never adds roles. Browser strategy is ignored unless browser roles are selected and included, so inactive incomplete fields cause neither validation errors nor metadata requests.

SetupStrategy is one of:

- {mode:'inherit',reasoning?:Reasoning,outputPolicy?:OutputPolicy}; defaults to inherit-compatible reasoning and preserved output. The UI exposes this deterministic strategy under advanced options. Already matching resources are unchanged, not a reason to write or clamp an override to the current Session.
- {mode:'fixed',provider,model,reasoning?:Reasoning,outputPolicy?:OutputPolicy}; defaults to model-default reasoning and preserved output. Reasoning is model-default or an explicitly supported fixed effort, never an old incompatible inherited effort.
- {mode:'auto',candidates:ModelCandidate[],defaultCandidate:string}; 1–3 complete native candidates, each with a stable unique id, purpose, provider/model, model-default or fixed reasoning, and positive integer maxTokens. Explicit strategies supply this list directly; AI strategies generate it from selected role responsibilities and resolved candidate routes. With a Session, candidates must be allowed by its explicit model policy. Without a Session, candidates come from configured model declarations and may include an unlisted generator model that resolved successfully. Session authorization is unknown until a Session is selected. The default is explicit, including after its candidate is deleted. There is no role-level output or reasoning override in the candidate list.

OutputPolicy is {mode:'preserve'}, {mode:'set',maxTokens:number}, or {mode:'clear'}. Preserve retains the current declaration/inheritance; clear authors output:null, not an omitted field. Migration is {mode:'candidate',candidateId:string} or {mode:'reset'}. Leaving auto mode requires this explicit per-role choice: copy the chosen old candidate's reasoning/output to the target role, or clear them to target defaults. Explicitly supplied shared candidates replace the old pool and own all new candidate resources; entering auto clears role-level output with a v2 override. YAML comments, extends, unrelated fields and enablement remain intact.

For explicit strategies, only deduplicated selected routes are resolved, plus the actual parent route when inheritance needs it. AI generation uses one native model request. The Host resolves the selected generator's exact metadata before enumerating candidates. Without a Session, provider enumeration returns available results after a 4 s budget and identifies failed or pending providers. Caller cancellation ends the enumeration wait and prevents a model stream. With a Session, candidate metadata is resolved from that Session's allowed explicit routes. It treats the response as untrusted proposal data and requires owner review before any configuration write. Metadata batches divide the deadline among bounded groups so stalled adapters release slots for later lookups. Refreshing model suggestions preserves the chosen generator and reviewed proposal. A failed suggestion list can be retried while typed model IDs remain usable. Every setup route requires text input. Native launch also rejects an explicitly declared lack of text support before it creates a snapshot. In both forms, missing exact metadata or unsupported effort blocks that row; Session denial and missing runtime plugins are advisory, not save authorization. Browser pools retain declared image candidates; filtering the default blocks the row until the owner chooses a valid default, never silently replaces it. Each candidate's output reservation is checked independently: any known zero input capacity blocks; all known capacities permit clamping to their minimum; any unknown capacity preserves the original input targets and reports uncertainty. Candidate cap prefill uses only an exact declared model default, never a guessed value, and cannot overwrite intervening edits.

Rows include id/title, roleRevision, optional expectedRevision/currentText/source, status:'changed'|'unchanged'|'preserved'|'blocked', applicable, before/after resources, reasons/warnings and proposedText only for actual changes. Generation returns independent rows before combination preview so one invalid combination does not discard valid suggestions. The UI stages strategy → relevant fields/scope → count summary and review, offers AI generation and one fixed model up front, and exposes explicit inheritance, manual candidates and resource migration under advanced options. No changes means no save operation.

Impact preflight compares every unselected resolved role against the original model/reasoning/output/context after **each possible saved prefix**, not just the final combination. This includes protected, source-owned, and excluded roles and newly restored descendants. A selected role ID can still have an indirect impact in another project if that project owns a definition with the same ID. Each impact is {id,title,before:Resources|null,after:Resources,prefixes:{afterId,resources}[]}. Preflight compares the global catalog and overlays from the current project and known live or persisted Sessions. Saves and all batch prefixes preserve roles already valid in any checked catalog. Reset may intentionally remove its direct target and preserves the other roles. The top-level impact has scope:'global' when it describes the global catalog outside a distinct current project view. When both scopes change differently, global supplies its own before, after and prefixes. Differences in other projects appear under projects, keyed by working directory with independent before, after and prefixes. A single confirmation covers the listed scopes for each role. impactRevision binds exact submitted text, revisions, policy, actor, catalog fingerprints and impact details. Any supplied revision must match the exact current preview, even when recomputation finds no indirect impacts. Changed setup inputs or scope stale the proposal. Changed submission subsets or drafts invalidate the affected consent. The Host rejects with `AGENTDECK_IMPACT_PREVIEW_REQUIRED`, `AGENTDECK_IMPACT_PREVIEW_CHANGED`, or `AGENTDECK_IMPACT_CONSENT_REQUIRED`. A legacy write without indirect impacts may proceed without a preview unless it uses the existing strategy contract.

The detail Session selects read-only evidence. Explicitly entering project edit binds a draft to that configuration context. Setup selects its own project and authorization context, and the runs filter selects a recorded parent separately. Writes go to the shared plugin-owned override layer and apply to future starts. Running tasks keep the pinned revision. Candidate mode chooses an owner-configured route.

## UI scope

Provide complete native settings management: searchable role list, role detail, real model/effort dropdowns (save as YAML override using core shape), effective context preview, enable/disable, raw YAML editor, create/derive/import/export/reset, diagnostics, task list and results. No fake run data or efficiency claims. Defaults use inherited current model. UI launch of tasks is optional because the main agent owns dispatch; do not add an alternate execution engine. Save/reset errors and dirty drafts remain visible. Direct settings changes take effect for new starts; running revisions remain pinned. Derivation drafts use the selected saved base's schema version; switching bases cannot rewrite imported raw definitions. Clearing a v2 non-auto inherited output cap authors output:null in the override while the normalized form has no output field, so later edits, save and reload do not restore the inherited cap.

Successful catalog reloads intersect the setup role scope with current valid roles, preserving valid choices and unsaved drafts without selecting additional roles. Selected-change impact previews update every displayed role, including source-owned and excluded browser roles, while those rows remain nonselectable. Pending or incomplete impact results block apply; clearing all selected changes resets every displayed after-resource value to its before value.

## Source layout

The static Client lives in src/client, translations in locale, and state/transport checks in test/client-*.test.mjs. locale/en.json and locale/zh.json are the single dictionary sources embedded by scripts/build-client.mjs. Native locale state drives labels and live settings registration; other languages fall back to English. AgentView.presentation adds localized input/deliverable/skill display without changing canonical definitions, instructions, custom prose or hashes. Stable diagnostic codes/parameters translate known messages; original diagnostics remain available. Native rc.3 preset names/descriptions accept plain strings, so new native presets and default child descriptions use stable Chinese/English text while historical snapshots and user descriptions remain unchanged. Host operations are shared by native agent tools and the owner management page. Preserve the existing DSH settings surface rather than introducing a separate app or execution loop.
