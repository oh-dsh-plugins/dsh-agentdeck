# Static Client and Host operation contract

This installed plugin uses the public Connection RPC carrier. When connection and webServer are available, Host registers connection.rpc.handle('/agentdeck', handler) and accepts namespaced agentdeck.* methods. The native API Gateway owns the exclusive shared /api interceptor. On the pinned 0.2.2-rc.3 baseline, explicitly call the public HostConnectionService.prototype rpc getter with the consumer service proxy; ordinary getter access shadows the dependency context and makes native handle() unable to read webServer. Both dependencies must still be declared by the consumer. This binding changes no service state or native registration logic. The dedicated channel retains native Host/Origin and authentication checks. Its handler admits only owner peers, validates payloads, and calls the same operation functions used by agent tools. UI-only save/reset/import operations are not model authority grants and must never mutate native model authorization.

## Client integration

Author src/client/index.js as one self-contained window.__ModuleLoader__.load({id:'dsh-agentdeck',factory(require){...}}) factory. React=require('react'); return {inject:['slots','locale','connection'],apply(ctx){...}}. No React copy, external client package imports, CDN, raw API fetch, or alternate app root. Use ctx.get('connection').rpc.call('/agentdeck', endpoint, payload, signal), unwrap the returned result DIRECTLY ({ok:true,value}|{ok:false,error}); connection.rpc.call does not return an outer response.result wrapper. Register settings.section id='agentdeck', order=30, label localized via ctx.locale; settings.section.icon keyed 'agentdeck' optional. Exact slot has close owner prop plus standard usePanelInfo/useSessions hooks. Can run without active Session; an optional explicit session id selects Session-authorized metadata. Use native theme tokens only (bg-base/layer-1/layer-2, border-l1/l2, label-primary/secondary, brand-primary, state-error/success/warn/idle-primary). Route all visible copy through registered zh/en locale dictionary. Maintain abort-on-unmount. Catalogue/models/preview/runs/result reads have a 15000 ms Client deadline, abort their carrier on timeout, end the busy state even if a carrier does not settle, preserve drafts, and expose a localized retryable error. Superseded/unmounted reads remain silent. Save/reset have no automatic deadline or replay. Show a preview only when both role id and revision match the current definition. Runtime capability evidence is retained per role, revision and selected Session so switching roles does not make a previously verified list row contradict its detail. Starting a refresh cancels the preceding preview and clears all evidence before loading the catalog; starting any preview clears that role’s earlier evidence. Candidate detail facts require a matching candidate; list authorization still describes the saved default. Failed or timed-out previews leave list/detail readiness unverified until a current request succeeds; late responses cannot restore expired evidence.

## Operations and shapes

- agentdeck.catalog payload {sessionId?:string}: {agents: AgentView[], diagnostics: {id?,source?,message}[], overrides: {id,text,revision}[], runtime:{compatibilityVersion:string,nativeProvider:boolean,storage:boolean}, sessions:{id,title?,cwd?}[]}.
- AgentView is AgentDefinition (docs/core-contract.md) plus revision:string, available:boolean, capabilitiesAvailable:boolean, authorization:{status:'unknown'|'authorized'|'denied',code?,policy?,route?,allowedModels?,message?}, configuredSelection?, missingCapabilities:string[], unverifiedCapabilities:string[], capabilityCheck:'static', builtin:boolean. `capabilitiesAvailable` records capability/enablement readiness; `available` additionally requires the saved default route to be authorized for the selected Session. No Session means unknown authorization and `available:false`. Catalog reads sample the Session policy once and do not discover model metadata. Matching live preview evidence can update list capability readiness, while a candidate preview must retain the saved default authorization in the list. Invalid candidate previews remain unavailable/unverified. Denial code `AGENTDECK_MODEL_NOT_AUTHORIZED` carries allowed explicit routes and owner recovery: change the saved role model or configure native model-selection settings and create a new Session; settings do not grant a restored Session new routes. AgentView also has browserSupport:{backend:'mcp'|'bsk'|'none',state:'ready'|'unverified'|'unsupported',reason:string,allowedNames:string[]}. Readiness means admitted tools, with live native connection checks still required. Static advisory reads must not initialize dynamic ToolSets or audit historical presets. Unknown dynamic capability is distinct from a proven missing prerequisite; actual child resolution/guards still apply. Model discovery is not authorization.
- agentdeck.models payload {sessionId?:string,provider?:string,model?:string,view?:'options'}: {providers:{id,name}[],models:ModelView[],selection?:{provider,model,reasoningEffort?},policy:'session'|'parent-only'|'not-selected'|'unresolved',diagnostics:string[]}. Explicit unscoped tool queries retain full-directory metadata behavior. GUI options mode with no provider reads only registered provider names; with provider it lists only that provider without per-row metadata; provider+model resolves only that route. A provider list does not gate exact metadata. Candidate provider and model fields are native select controls backed by registered providers and that provider's configured model options. The Client scopes option membership, busy/error state, deadlines and retry identity by provider; exact metadata is scoped by provider/model. Lists load lazily on focus or route selection, share only within the same provider and never resolve every candidate's metadata. Missing saved values remain explicit unavailable/unchecked options rather than being silently rewritten. Changing a candidate route clears only that candidate's effort, retaining its output cap, the default candidate and other candidates. The Client stores option membership separately from exact metadata, replaces list membership on refresh and exposes list diagnostics with retry.
- ModelView: {provider,id,name,authorized:boolean|null,metadataResolved:boolean,contextWindow?:number,defaultMaxTokens?:number,efforts?:{id,name,description?}[],defaultEffort?:string,inputModalities?:string[],error?:string}. Unresolved options omit efforts rather than claiming an empty supported set. An exact request includes exact metadata even if the catalogue omitted it. A non-session view has authorized:null. Unknown values must remain unknown.
- agentdeck.preview payload {id:string,sessionId?:string,candidateId?:string,revision?:string}: {agent:AgentView,model?:ModelView,configuredSelection?,effectiveSelection?,sessionSelection?,authorization:{status:'unknown'|'authorized'|'denied',message?},output:{configuredMaxTokens?,effectiveMaxTokens?,source:'candidate'|'role'|'parent'|'native-default'|'unknown',validated:boolean},capacity:{kind:'configured'|'validated-parameters'|'unknown',assemblyChecked:false},budget:{known,targetTokens,elasticTokens,safeInputTokens?,headroomTokens,materialTokens?,diagnostics},diagnostics:string[]}. Fixed/auto metadata can resolve without a Session; authorization is unknown and the cap is configured only. A denied route retains declaration metadata. Unmeasured fixed prompt/tool cost means materialTokens is omitted; safeInputTokens is total-input capacity, not a free-material estimate. Actual execution still validates assembly.
- agentdeck.candidates payload {id:string,sessionId?:string}: {id,revision,mode,defaultCandidate?,candidates:{id,purpose,provider,model,reasoning,maxTokens,authorization:'unknown'|'authorized'|'denied'}[]}. Only this role's compact pool is returned, without instructions, other pools or model directory/metadata calls. Auto starts require this revision; candidateId and candidateReason are optional, the default is explicit, and invalid/unauthorized/stale choices never start another candidate.
- agentdeck.save payload {id:string,text:string,expectedRevision?:string,sessionId?:string}: {id,revision,text}. Text is a YAML schemaVersion=1|2 override; a new role uses extends or a complete definition. expectedRevision is mandatory for replacing an existing override. Validation and CAS share one serial commit boundary and include selected-Session project/custom sources. External source-owned ids must be edited in their owning file or derived to a fresh id, because file precedence would hide a user-store write. Root factory definitions remain immutable. Unknown/missing roles are errors; there is no silent general replacement. Same text can be exported directly.
- agentdeck.reset payload {id:string,expectedRevision:string,sessionId?:string}: {id,reset:true}. Deletes only this override from plugin-owned store, not files or factory data. Model-facing save/reset may not re-enable or expand capabilities/scripts or change model/candidates, reasoning, output or input resource policy. Owner UI operations retain those configuration rights within native authorization.
- Owner-only agentdeck.recommend payload {roleIds:string[],defaultRoute:{provider,model},imageRoute?:{provider,model},includeBrowser?:boolean,sessionId?:string}: {rows,models,diagnostics}. Only the selected routes are resolved (at most two); no inference, model-directory fanout, paid requests, persistence or performance/cost ranking. Each row includes id/title, roleRevision, optional expectedRevision/currentText, applicable, localized diagnostic codes, before/after resources and proposedText. Fixed model plus model-default reasoning preserves other YAML fields, comments and inheritance. Browser roles require declared image input. Capacity estimates use the same role-over-parent output selection as native delegation; no-Session estimates disclose the model-default assumption. An exhausted inherited Session output limit is advisory and preserves existing input targets. Failed route metadata includes one deduplicated diagnostic with code/params and an original cause, shown under a localized expandable disclosure. Session denial and runtime prerequisites are warnings, not configuration-save gates. External source-owned roles are not rewritten.
- Owner-only agentdeck.previewSetup payload {rows:{id,text,roleRevision,expectedRevision?}[],sessionId?:string}: {resources:{[roleId]:{model,reasoning,output?,context}}}. It reuses apply preflight and resolves the entire selected inheritance combination without persistence or model calls. Recommendation after-resources initially reflect all applicable rows; the Client rechecks the exact clean checked subset, including after checkbox changes. While that read is pending or failed, stale after-values are hidden and apply is disabled. Obsolete responses cannot overwrite a newer subset. All catalog reloads cancel prior role previews and clear both the global detail preview and per-role evidence, including unchanged revisions.
- Owner-only agentdeck.applySetup payload {rows:{id,text,roleRevision,expectedRevision?}[],sessionId?:string}: {status:'completed'|'stopped',rows:{id,status:'applied'|'failed'|'uncertain'|'not-run',revision?,message?}[]}. Preflight validates the full selected catalog and every inheritance prefix before writing. Base roles precede derived roles; the existing serial store boundary excludes concurrent save/reset writes, and each prefix rechecks catalog/source revisions. First failure stops remaining rows and retains confirmed writes. No cross-role atomicity, persistent journal, resume or restore promise. Writes have no automatic client deadline/replay. A lost response triggers catalog readback; exact matching text is reported as observed, not attributed to that request. Unknown outcomes require owner review. Canceled or superseded readback remains silent and must not publish obsolete reconciliation rows after a Session change or newer catalog read; an actual readback failure still reports unknown outcomes.
- agentdeck.runs payload {sessionId?:string}: {runs:RunView[]}.
- RunView: {id,roleId,revision,parentId,childId?,description,createdAt,phase:'starting'|'accepted'|'uncertain'|'failed',error?,model?:{provider,model,reasoningEffort?,maxTokens?},decision?:{candidateId,roleRevision,source:'default'|'recommended'|'legacy-route',reason?},nativeStatus?:string,businessStatus?:string}.
- agentdeck.result payload {childId:string,sessionId?:string,offset?:number,limit?:number}: {childId,status,summary,evidence?:unknown[],coverage?:unknown,artifacts?:unknown[],limitations?:unknown[],rawText:string,totalCharacters:number,nextOffset?:number,usage?:unknown,nativeStop?:unknown}. Details are paged; no false completed solely on idle. The latest native turn and stop reason constrain completion claims. A single structured evidence/artifact/limitation value is normalized to an array rather than discarded. Native usage is reported only where available; absent counters remain null and a wholly unreported usage record is null. Runs queries reconcile uncertain receipts against native catalogue and exact parent/preset metadata without creating work.

## UI scope

Provide complete native settings management: searchable role list, role detail, real model/effort dropdowns (save as YAML override using core shape), effective context preview, enable/disable, raw YAML editor, create/derive/import/export/reset, diagnostics, task list and results. No fake run data or efficiency claims. Defaults use inherited current model. UI launch of tasks is optional because the main agent owns dispatch; do not add an alternate execution engine. Save/reset errors and dirty drafts remain visible. Direct settings changes take effect for new starts; running revisions remain pinned. Derivation drafts use the selected saved base's schema version; switching bases cannot rewrite imported raw definitions. Clearing a v2 non-auto inherited output cap authors output:null in the override while the normalized form has no output field, so later edits, save and reload do not restore the inherited cap.

Successful catalog reloads intersect the setup role scope with current valid roles, preserving valid choices and unsaved drafts without selecting additional roles. Selected-change impact previews update every displayed role, including source-owned and excluded browser roles, while those rows remain nonselectable. Pending or incomplete impact results block apply; clearing all selected changes resets every displayed after-resource value to its before value.

## Source layout

The static Client lives in src/client, translations in locale, and state/transport checks in test/client-*.test.mjs. locale/en.json and locale/zh.json are the single dictionary sources embedded by scripts/build-client.mjs. Native locale state drives labels and live settings registration; other languages fall back to English. AgentView.presentation adds localized input/deliverable/skill display without changing canonical definitions, instructions, custom prose or hashes. Stable diagnostic codes/parameters translate known messages; original diagnostics remain available. Native rc.3 preset names/descriptions accept plain strings, so new native presets and default child descriptions use stable Chinese/English text while historical snapshots and user descriptions remain unchanged. Host operations are shared by native agent tools and the owner management page. Preserve the existing DSH settings surface rather than introducing a separate app or execution loop.
