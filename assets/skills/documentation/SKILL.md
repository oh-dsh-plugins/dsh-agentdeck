# Documentation

Use when creating or updating instructions, guides, reference material or explanatory documents.

1. Identify the audience, task and desired outcome. Read the current implementation or authoritative material. Verify exact command names, flags, schemas and supported versions before describing them.
2. Organize around the reader's task. Lead with the result, then give prerequisites, concise steps, a realistic example, expected output and actionable failures. Keep reference details separate when they interrupt the main flow.
3. Write plain prose with concrete terms. Explain a technical term at its first material use. Keep names and examples consistent. Instruction and skill files use English unless the task explicitly requests another language.
4. Edit only authorized documentation paths and owned examples. Preserve relevant existing content and links. Do not turn speculative features into present-tense promises or alter application behavior merely to simplify the guide.
5. Check links and source locations, example syntax and consistency with actual behavior. Run an existing documentation check only when execution is authorized. Clearly label an example that could not be executed.

Deliver complete prose and usable examples. Empty headings, TODO placeholders and generic templates do not satisfy a requested document. State prerequisites that a reader needs before the relevant step, especially credentials, authority or effects that influence the decision to proceed. Keep verification claims tied to observed checks; documentation review cannot establish runtime behavior that was not exercised. Finish with a concise handoff describing the resulting content and material verification limits.
